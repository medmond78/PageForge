# PageForge Markdown Guide for LLM Agents

This guide provides best practices for LLM agents generating markdown documents for PageForge PDF conversion.

## Quick Reference Checklist

Before generating or converting markdown, verify:

- ✅ **Blank lines before all lists** (most common issue)
- ✅ All image paths are relative and files exist
- ✅ Code blocks specify language for syntax highlighting
- ✅ Tables fit in portrait orientation (or set landscape in frontmatter)
- ✅ No unsupported features (embedded video, JavaScript)
- ✅ Frontmatter YAML is valid
- ✅ Alt text is descriptive (becomes image caption)
- ✅ Consistent heading hierarchy (don't skip levels)

## Critical Rule: Blank Lines Before Lists

**This is the #1 issue with LLM-generated markdown.**

Standard markdown (CommonMark) requires a blank line before list items. Without it, lists render as dashed text in paragraphs instead of proper bullet points.

### ❌ Wrong (No Blank Line)

```markdown
The requirements include:
- ISO 13485:2016 compliance
- Risk-based validation
- Design control integration
```

**Result:** Renders as paragraph with dashes, not a list.

### ✅ Correct (Blank Line Before List)

```markdown
The requirements include:

- ISO 13485:2016 compliance
- Risk-based validation
- Design control integration
```

**Result:** Renders as proper bulleted list with indentation.

### Nested Lists

Nested lists also need blank lines:

```markdown
Main workflow steps:

1. Planning phase
   - Define scope
   - Assess risk
   - Create protocol

2. Execution phase
   - Install software
   - Run benchmarks
   - Document results
```

## Directory Structure

Organize files with images in predictable locations:

```
project/
  report.md
  image1.png
  image2.svg
```

Or use a subdirectory:

```
project/
  report.md
  images/
    chart1.png
    diagram.svg
```

## Image References

### ✅ Always Use Relative Paths

```markdown
![Chart](./chart.png)
![Diagram](./images/diagram.svg)
![Data visualization](../shared/graph.png)
```

### ❌ Never Use Absolute Paths or URLs

```markdown
❌ ![Bad](C:\Full\Path\image.png)
❌ ![Bad](/absolute/path/image.png)
❌ ![Bad](https://example.com/image.png)
```

**Why:** Absolute paths break portability, remote URLs aren't embedded in PDF.

### Descriptive Alt Text

Alt text becomes the image caption in the PDF. Be descriptive:

```markdown
✅ ![Monthly revenue trends showing 12% growth from July to August](./revenue-chart.png)
❌ ![image](./revenue-chart.png)
❌ ![chart1](./revenue-chart.png)
```

## Code Blocks

### Always Specify Language

Enables syntax highlighting in the PDF:

````markdown
```python
def process_data(data):
    """Process and analyze data."""
    return [x * 2 for x in data]
```
````

Supported languages: `python`, `javascript`, `java`, `c`, `cpp`, `csharp`, `ruby`, `go`, `rust`, `sql`, `bash`, `shell`, `yaml`, `json`, `xml`, `html`, `css`, `markdown`

### Keep Lines Under 80 Characters

Long lines in code blocks may wrap awkwardly:

````markdown
```python
# ✅ Good: readable line length
def calculate_metrics(data):
    revenue = sum(x.revenue for x in data)
    return revenue

# ❌ Bad: very long line
def calculate_metrics(data): return {"revenue": sum(x.revenue for x in data), "profit": sum(x.profit for x in data), "customers": len(data)}
```
````

## Tables

### Keep Tables Concise for Portrait

Tables should fit in portrait orientation (default):

```markdown
| Metric | Value | Change |
|--------|-------|--------|
| Revenue | $150K | +12% |
| Users | 1,200 | +8% |
| Churn | 2.3% | -0.5% |
```

### Wide Tables: Use Landscape

For tables with many columns, set landscape orientation in frontmatter:

```markdown
---
title: Quarterly Report
pageforge:
  page:
    orientation: landscape
---

| Q1 Rev | Q1 Profit | Q2 Rev | Q2 Profit | Q3 Rev | Q3 Profit | Q4 Rev | Q4 Profit |
|--------|-----------|--------|-----------|--------|-----------|--------|-----------|
| $100K  | $20K      | $120K  | $25K      | $150K  | $35K      | $180K  | $45K      |
```

## Document Structure

### Use Consistent Heading Hierarchy

Start with H1, use H2 for sections, H3 for subsections:

```markdown
# Main Title (H1)

## Section (H2)

### Subsection (H3)

Content...

#### Detail Level (H4)

More specific content...

## Next Section (H2)
```

**❌ Don't skip levels:**

```markdown
# Main Title (H1)

### Subsection (H3)  ❌ Skipped H2
```

### YAML Frontmatter

Include metadata at the top of the document:

```yaml
---
title: Report Title
author: Generated by Claude
date: 2026-08-12
---
```

Valid frontmatter keys:
- `title`: Document title
- `author`: Author name
- `date`: Publication date (YYYY-MM-DD format)
- `pageforge`: PageForge configuration overrides (see Configuration section)

## Line Length and Formatting

### Natural Line Breaks

Keep paragraph line length reasonable (no 500-character single lines):

```markdown
✅ This is a paragraph with reasonable line length.
It's easier to read and edit when lines wrap naturally.

This is another paragraph with similar formatting.

❌ This is a very long single-line paragraph that goes on and on without any line breaks making it difficult to read and edit in a text editor and should be avoided when generating markdown content programmatically.
```

### Inline Formatting

Standard markdown formatting works:

```markdown
**Bold text**
*Italic text*
`inline code`
[Link text](https://example.com)
```

## Special Characters

Most special characters work fine. For characters that conflict with markdown syntax, use HTML entities:

- `&lt;` for <
- `&gt;` for >
- `&amp;` for &
- `&quot;` for "

## Complete Example Template

Here's a complete template following all best practices:

```markdown
---
title: Quarterly Analysis Report
author: Generated by Claude
date: 2026-08-12
---

# Quarterly Analysis Report

## Executive Summary

This report analyzes Q3 2026 performance metrics and identifies key trends.

**Key Findings:**

- Revenue increased 12% quarter-over-quarter
- Customer acquisition improved by 8%
- Churn rate decreased by 0.5 percentage points

## Detailed Analysis

### Revenue Trends

The following chart shows monthly revenue progression:

![Monthly revenue trends showing steady 12% growth from July to August with slight acceleration in September](./charts/revenue-trend.png)

Revenue growth was driven by:

1. Enterprise customer expansion
2. New product line launches
3. International market entry

### Customer Metrics

Performance metrics for Q3:

| Metric | Q2 | Q3 | Change |
|--------|-----|-----|--------|
| Revenue | $100K | $112K | +12% |
| Customers | 1,100 | 1,188 | +8% |
| Churn | 2.8% | 2.3% | -0.5% |

### Technical Implementation

We implemented the following optimization:

```python
def optimize_revenue_model(customer_data):
    """
    Optimize revenue predictions using Q3 data.
    
    Args:
        customer_data: List of customer records
        
    Returns:
        Optimized revenue forecast
    """
    high_value = [c for c in customer_data if c.ltv > 10000]
    return sum(c.predicted_revenue for c in high_value)
```

## Recommendations

Based on the analysis, we recommend:

1. **Increase enterprise focus**
   - Expand sales team by 20%
   - Develop enterprise feature set
   - Create dedicated support tier

2. **Accelerate product launches**
   - Target 2 new products in Q4
   - Prioritize customer feedback
   - Fast-track beta programs

3. **Reduce churn further**
   - Implement early warning system
   - Increase customer success touchpoints
   - Develop retention incentive program

## Conclusion

Q3 demonstrated strong growth across all key metrics. Continued focus on enterprise customers and product innovation positions us well for Q4 targets.

---

**Report generated:** 2026-08-12  
**Next review:** 2026-11-12
```

## Validation Workflow

After generating markdown:

1. **Convert with PageForge:**
   ```bash
   pageforge report.md output.pdf
   ```

2. **Open PDF and verify:**
   - All lists render as bullet points (not dashed text)
   - Images are embedded correctly
   - Code blocks have syntax highlighting
   - Tables fit within page margins
   - Heading hierarchy is clear

3. **Fix common issues:**
   - Add blank lines before lists
   - Verify image paths are relative
   - Check table width
   - Validate YAML frontmatter

## Common Mistakes to Avoid

### 1. Missing Blank Lines Before Lists

**Most common issue.** Always add blank line before list items.

### 2. Absolute Image Paths

Use `./image.png` not `C:\path\to\image.png`

### 3. Generic Alt Text

Use `![Revenue growth chart showing 12% increase](./chart.png)` not `![image1](./chart.png)`

### 4. Skipping Heading Levels

Don't go H1 → H3, use H1 → H2 → H3

### 5. Missing Language in Code Blocks

Always specify: ` ```python ` not just ` ``` `

### 6. Tables Too Wide

Test in portrait first, use landscape frontmatter if needed

### 7. No Frontmatter

Include at minimum:
```yaml
---
title: Document Title
date: 2026-08-12
---
```

## Configuration Overrides

You can override PageForge settings in frontmatter:

```yaml
---
title: Technical Report
pageforge:
  page:
    orientation: landscape
    size: a4
  fonts:
    body_size: 11
  images:
    max_width: 7.0
    max_height: 8.5
---
```

See `docs/user-guide.md` Configuration section for all available options.
